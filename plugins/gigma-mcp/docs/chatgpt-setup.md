# Gigma MCP в ChatGPT

Эта инструкция относится к пакету Gigma MCP и существующему серверу владельца
проекта. Она проверяет подключение инструментов к ChatGPT. Вход владельца
проходит отдельно через подтверждение звонком.

## Параметры подключения

| Параметр | Значение |
| --- | --- |
| Название | Gigma MCP |
| MCP URL | `https://api.auth.gigma.ru/mcp/owner/` |
| Транспорт | Streamable HTTP |
| Авторизация транспорта | None (`auth.type: none`) |
| Вход владельца | Native callback через `erp_dialog_*` |
| Исходный пакет | `plugins/gigma-mcp` в этом репозитории |

Сохраните завершающий `/` в URL: адрес без него может перенаправлять POST.
Ссылка на GitHub, страница сайта и MCP URL выполняют разные задачи.

**None относится к обнаружению инструментов.** Доступ к данным проекта
проверяет сервер по подтверждённой сессии владельца. Пакет не отключает эту
проверку и не содержит токенов, паролей или готовых сессий.

Установка marketplace в Codex на компьютере не подключает Gigma к ChatGPT web.
Для веб-чата нужен установленный облачный плагин с доступными MCP-инструментами.
Если Gigma уже есть в вашем аккаунте, сначала используйте его карточку и
диагностику подключения. Не создавайте второй плагин только для обновления
списка инструментов.

## Установка полного пакета

Этот вариант сохраняет MCP-подключение и все шесть навыков: настройку, вход,
маршрутизацию запросов, операции проекта, подписки и расследование контрагентов.

1. Получите проверенный архив одного плагина. Из checkout репозитория он
   собирается командой `python build_chatgpt_package.py`.
2. Передайте архив в Plugin Creator и попросите сохранить его как приватный
   плагин Gigma MCP с существующим сервером. Если уже существует редактируемый
   плагин, обновите его с сохранением идентичности.
3. Откройте возвращённую карточку и выполните доступные действия установки и
   подключения. Проверьте результат импорта: должны быть шесть навыков и
   удалённое подключение `gigma`. Успешная загрузка архива сама по себе этого
   не доказывает.
4. Выберите Gigma MCP через `@` в разговоре. Если инструменты ещё не появились,
   откройте новый разговор с этим же плагином.
5. Выполните [проверку в чате](#проверка-в-чате).

Архив содержит один каталог `gigma-mcp` с корневыми `plugin.json`, `mcp.json`,
навыками, документацией и проверкой контракта. Архив всего GitHub-репозитория
с marketplace не является этим установочным пакетом.

Пакет использует portable manifest Agent Plugins 1.0. Настройки представления
и начального запуска находятся в `extensions.com.openai`; аутентификация
транспорта — в `mcp.json`. Идентификаторы подключений `.app.json` нельзя
выдумывать: они применимы только к уже зарегистрированному App с подтверждённым
идентификатором.

## Прямое подключение MCP

Этот вариант добавляет инструменты сервера. Шесть навыков из GitHub автоматически
не импортируются; полный пакет выше включает их вместе с инструкциями.

1. В ChatGPT откройте **Plugins → + → Add custom MCP server**.
2. Укажите название **Gigma MCP** и описание:
   «Работа с проектом Gigma: приложения, тарифы, подписки и проверка платежей».
3. В Connection укажите `https://api.auth.gigma.ru/mcp/owner/`.
4. Выберите **None / No authentication** для транспорта.
5. Ознакомьтесь с предупреждением интерфейса и выберите **Create as a plugin**.
6. Проверьте обнаруженный список инструментов, установите полученный плагин и
   выберите его через `@` в новом разговоре.

Доступность добавления пользовательских MCP зависит от аккаунта и политики
рабочего пространства. Если интерфейс не позволяет создать подключение,
сохраните точное сообщение об ограничении; изменение JSON в репозитории не
предоставляет отсутствующие права.

Если ChatGPT требует OAuth ещё до выдачи `erp_dialog_*`, остановите эту попытку
и зафиксируйте несовпадение контракта. Не переключайтесь автоматически на OAuth,
не вставляйте API key и не вызывайте обходной REST endpoint. Поддерживаемый этим
пакетом вход владельца описан в [настройке клиента](mcp-client-setup.md).

## Проверка в чате

Сначала напишите:

> Проверь, какие инструменты Gigma доступны в этом разговоре. Пока не начинай вход владельца.

До входа должны быть доступны следующие инструменты native callback:

| Инструмент | Назначение |
| --- | --- |
| `erp_dialog_check` | Проверка существующей сессии или подготовка диалога |
| `erp_dialog_start` | Начало выбранного входа или регистрации после согласия |
| `erp_dialog_status` | Состояние текущего подтверждения |
| `erp_dialog_reconcile` | Явно запрошенное восстановление неопределённого результата |
| `erp_dialog_connect` | Завершение подтверждённого входа |
| `erp_dialog_me` | Данные текущего владельца и проекта |
| `erp_dialog_cancel` | Отмена незавершённого диалога |
| `erp_dialog_logout` | Завершение сессии владельца |

Каталог также должен содержать защищённые бизнес-инструменты, например
`erp_list_applications`. Их наличие в каталоге не предоставляет доступ к данным.
Число инструментов может меняться; ориентируйтесь на нужные имена и схемы.

После успешного обнаружения напишите:

> Подключи мой проект Gigma через подтверждение звонком.

Далее действует [native callback flow](mcp-client-setup.md#native-owner-login).
Агент использует действующую сессию, если она доступна. При новом входе он
получает номер владельца, предлагает один выбор входа или регистрации и
показывает номер для звонка после подготовки подтверждения. Не передавайте
токены, callback proof или capability в текст сообщения.

**Проверка завершённого входа:** `erp_dialog_me` вернул корректный проект;
последующее разрешённое чтение, например списка приложений, успешно. Проверка
метаданных и установка пакета не заменяют эти два шага.

## Диагностика

| Наблюдение | Следующий шаг |
| --- | --- |
| Плагин есть в Codex, но отсутствует в ChatGPT web | Установить или выбрать облачное подключение Gigma |
| Карточка есть, инструментов в разговоре нет | Проверить установку, подключение, результаты импорта и выбранный плагин |
| Инструменты прямого custom MCP устарели | Открыть подключение, выполнить Refresh, проверить метаданные и новый разговор |
| Проверка сервера успешна, инструментов в чате нет | Исследовать подключение ChatGPT; не объявлять сервер недоступным |
| HTTP 401/403 до обнаружения callback-инструментов | Зафиксировать ошибку транспорта/авторизации, не менять способ входа автоматически |
| HTTP redirect | Проверить точный URL с завершающим `/` |
| Состояние callback потеряно между сообщениями | Следовать bounded recovery; не просить пользователя вставить capability |
| Появились и карточка выбора, и текстовый вопрос | Проверить регистрацию и живые метаданные; не отвечать дважды |

Подробнее: [устранение неполадок](mcp-troubleshooting.md) и
[правила доступа](mcp-security-and-approvals.md).

## Проверки для разработчика

В корне checkout репозитория, Python 3.10 или новее:

```text
python validate_plugin.py
python -m unittest discover -s tests -v
python build_chatgpt_package.py
python check_live_contract.py --timeout 15
```

Сборка проверяет манифесты и свежесть включённых документов, создаёт
`dist/gigma-mcp-<version>-chatgpt.zip` и проверяет содержимое архива. Совместимые
манифесты Codex/Claude/Cursor остаются в репозитории; в ChatGPT ZIP используется
portable manifest. Для публикации новой версии загрузите заново собранный пакет.

Live checker делает только `initialize`, `notifications/initialized` и чтение
каталогов. Он не вызывает `tools/call`, не отправляет телефон и не запускает
callback. Успешный результат означает совместимость проверенных метаданных,
а не проверенный вход, возможность записи или готовность всего backend.
Версия `serverInfo.version` не определяет Git-коммит развёрнутого сервера.

Сохраните в отчёте версию пакета, Git SHA, результат live checker и отдельный
результат проверки инструментов в ChatGPT. Не сохраняйте идентификаторы
транспортной сессии, capabilities или персональные данные.
