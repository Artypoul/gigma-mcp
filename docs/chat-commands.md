# Команды Gigma из чата

Выберите подключённый Gigma MCP через `@` и напишите одну из фраз ниже.
Это обычные сообщения в чате: специальный синтаксис `/command` не требуется.
Имена `erp_*` обозначают реальные инструменты сервера. Клиент может добавить
к ним свой префикс; агент выбирает фактически доступный инструмент по его
имени, описанию и текущей схеме.

**Условие выполнения:** инструменты Gigma должны присутствовать в текущем
разговоре. Наличие этого документа, навыков или карточки плагина не создаёт
подключение. Если доступны только инструкции, агент сообщает об этом и
показывает [настройку ChatGPT](chatgpt-setup.md#команды-в-веб-чате-chatgpt).
Запрос меню не запускает вход и не требует телефона.

## Готовые фразы

| Что написать | Инструмент или последовательность | Условие |
| --- | --- | --- |
| **Гигма, команды** или **Гигма, помощь** | Агент показывает это меню и проверяет наличие инструментов в разговоре | Вход не нужен; вызовы Gigma не выполняются |
| **Гигма, подключись** | `erp_dialog_check` → выбор входа/регистрации → `erp_dialog_start` → `erp_dialog_status` → `erp_dialog_connect` → `erp_dialog_me` | Действующая сессия используется повторно; новый callback запускается после согласия |
| **Гигма, проверь звонок** | `erp_dialog_status`, затем `erp_dialog_connect`, если подтверждение завершено | Уже начатая попытка; новый звонок не запускается |
| **Гигма, отмени вход** | `erp_dialog_cancel` | Незавершённая попытка |
| **Гигма, мой проект** | `erp_dialog_me` | Подтверждённая сессия владельца |
| **Гигма, приложения** | `erp_list_applications` | Подтверждённая сессия владельца |
| **Гигма, покажи приложение …** | `erp_get_application` | Приложение однозначно найдено |
| **Гигма, клиенты приложения …** | `erp_list_service_clients` | Показываются безопасные метаданные без секретов |
| **Гигма, тарифы приложения …** | `erp_subscription_plans_list` | Выбрано приложение |
| **Гигма, версии тарифа … в приложении …** | `erp_subscription_plan_revisions_list` | Выбраны приложение и тариф |
| **Гигма, общий каталог** | `erp_subscription_catalog_entries_list` | Каталог текущего рабочего пространства |
| **Гигма, все активные подписки** | `erp_workspace_subscriptions_list` | Фильтр состояния берётся из текущей схемы |
| **Гигма, подписки приложения …** | `erp_subscriptions_list` | Выбрано приложение |
| **Гигма, история подписки … в приложении …** | `erp_subscription_status_events_list` | Выбрана подписка |
| **Гигма, платёжные инциденты приложения …** | `erp_payment_review_cases_list` | Чтение списка; исправления не запускаются |
| **Гигма, найди контрагента по …** | `erp_find_counterparty` | Телефон или email; неоднозначность уточняется |
| **Гигма, история контрагента …** | `erp_counterparty_investigate` | Один идентификатор или телефон, результаты с редактированием чувствительных данных |
| **Гигма, журнал активности …** | `erp_activity_logs_inspect` | Уточняются цель, период и допустимые фильтры |
| **Гигма, создай приложение …** | Чтение текущего состояния → план → подтверждение → `erp_create_application` | Нужны уникальный ID, название и тип приложения |
| **Гигма, отключись** | `erp_dialog_logout` | Отзывается текущая сессия владельца |

Можно писать свободнее: «Покажи мои приложения в Гигма» и «Гигма, приложения»
означают одну задачу. Можно назвать точный инструмент: «Вызови
`erp_list_applications` для моего текущего проекта». Это не обходит проверку
сессии, прав или подтверждение изменений.

## Как передавать параметры

Для списка приложений достаточно самой команды. Для тарифов, клиентов,
подписок и платежей назовите приложение; агент сначала прочитает доступные
объекты и выберет их канонические имена. Если совпадений несколько, он
уточнит выбор. Для списков можно указать период, состояние и другие фильтры,
которые действительно поддерживает текущая схема.

Не нужно составлять JSON, знать ETag или передавать внутреннюю capability.
Агент берёт ETag из свежего чтения, а необходимые служебные идентификаторы
удерживает в защищённом состоянии инструментов. Сессия определяет рабочее
пространство; текст сообщения не переключает владельца или tenant.

Вход выполняется через существующие callback-ручки Gigma. Авторизация
транспорта **No authentication** разрешает обнаружить инструменты; доступ к
данным появляется после подтверждения владельца. Меню команд и обнаружение
инструментов не требуют callback. Пароли, OAuth-токены, ключи провайдеров и
capabilities в сообщения не вставляются.

Операции с отметкой **изменение** требуют чтения текущего состояния, понятного
плана и подтверждения. Неопределённый результат не означает, что операция
не выполнилась: агент использует предусмотренную конкретной схемой проверку
и не создаёт повторную операцию вслепую. Подробности — в
[правилах доступа](mcp-security-and-approvals.md).

**Gigma Auth: MCP Owner 1.30.0**, протокол **2025-06-18**, **77 инструментов**.

доступности всех инструментов в конкретном чате. При выполнении приоритет

## Что считать успешной проверкой

1. В выбранном чате обнаружены фактические `erp_dialog_*` и нужный
   бизнес-инструмент. Для этой проверки не вызывайте `erp_dialog_check`:
   он может подготовить попытку входа.
2. После отдельного запроса пользователя на вход callback завершается,
   а `erp_dialog_me` подтверждает нужный проект.
3. Запрос **«Гигма, приложения»** вызывает `erp_list_applications` и
   возвращает результат текущего проекта. Пустой список тоже может быть
   корректным результатом.

Успешная сборка ZIP, проверка Codex или ответ `tools/list` с сервера не заменяют
эту проверку в ChatGPT. Склады, товары, заказы, витрины и miniapps не входят
в этот owner MCP; выдумывать для них команды нельзя.
