# Gigma MCP в ChatGPT: команды и подключение

Источник marketplace: **https://github.com/Artypoul/gigma-mcp**. Репозиторий
содержит один плагин **Gigma MCP**: шесть навыков и конфигурацию удалённого
сервера `gigma`. Вход в проект Gigma выполняется после установки, через
подтверждение звонком.

[Каталог команд](chat-commands.md) содержит готовые фразы и все 77 имён
из проверенного серверного каталога. Чтобы их выполнять, ChatGPT должен
предоставить реальные инструменты в выбранном разговоре.

## Команды в веб-чате ChatGPT

Для веб-чата используйте зарегистрированное подключение к существующему
MCP-серверу. Если такое подключение Gigma уже есть, откройте его и проверьте
инструменты; второе подключение создавать не нужно. Если его нет,
поддерживаемый путь: **Plugins → + → Add custom MCP server**.

| Поле | Значение |
| --- | --- |
| Name | `Gigma MCP` |
| Description | Команды Gigma для владельца проекта; вход через callback-звонок |
| Connection | Публичный HTTPS endpoint |
| Server URL | `https://api.auth.gigma.ru/mcp/owner/` |
| Transport, если показывается | Streamable HTTP |
| Authentication | **No authentication** / None |

Нажмите **Create as a plugin**, проверьте обнаруженные инструменты, установите
получившийся плагин и выберите его через `@` в новом разговоре. Напишите
**«Гигма, команды»**. Проверка должна назвать реально предоставленные
инструменты; имя из документации не считается найденным инструментом.
Порядок описан в [официальной инструкции подключения](https://developers.openai.com/plugins/deploy/connect-chatgpt).

**Callback-авторизация Gigma остаётся прежней.** No authentication относится
к обнаружению MCP. Команды `erp_dialog_check → erp_dialog_start →
erp_dialog_status → erp_dialog_connect` подтверждают владельца внутри Gigma.
Добавление подключения не требует заменять этот процесс Google-входом,
OAuth или API-ключом. Запрос меню также не запускает вход владельца.

Когда инструменты появились, запрос **«Гигма, подключись»** запускает
существующий native flow; при действующей сессии повторный callback не нужен.
После подтверждения запрос **«Гигма, приложения»** должен вызвать
`erp_list_applications`. До этой проверки нельзя утверждать, что команды
работают в ChatGPT, даже если серверный `tools/list` успешен.

### Привязка пакета к приложению как у GitHub

В публичном [пакете GitHub](https://github.com/openai/plugins/tree/main/plugins/github)
файл [.app.json](https://github.com/openai/plugins/blob/main/plugins/github/.app.json)
содержит ссылки на зарегистрированные приложения, а
[manifest](https://github.com/openai/plugins/blob/main/plugins/github/.codex-plugin/plugin.json)
указывает на этот файл. Для Gigma используется собственный App ID; ID GitHub
и его настройки авторизации к Gigma не относятся.

После регистрации Gigma возьмите **реальный App ID** из карточки подключения.
Для URL с техническим ID `plugin_asdk_app_…` соответствующий App ID имеет
вид `asdk_app_…`. Обычный `plugins_…` или `plugin_…` ID архивного плагина
не является App ID. Проверьте, что выбранное приложение указывает именно
на endpoint Gigma и предоставляет его инструменты.

Для личного или рабочего пакета задайте `GIGMA_CHATGPT_APP_ID` этому
проверенному значению и выполните в checkout репозитория:

```text
python build_chatgpt_package.py --chatgpt-app-id "$GIGMA_CHATGPT_APP_ID"
```

Результат — `dist/gigma-mcp-<version>-chatgpt-app.zip`: те же шесть навыков,
каталог команд, обязательная ссылка `apps.gigma` в `.app.json` и
`extensions.com.openai.apps: "./.app.json"` в `plugin.json`. В этой копии
нет `mcp.json` и совместимых MCP-манифестов, поэтому она не объявляет сервер
повторно. Исходный marketplace и обычная сборка остаются прежними.

Сборщик проверяет формат ID, но не регистрацию, владельца или разрешения.
`.app.json` не создаёт приложение и не выдаёт доступ. При обновлении
существующего архивного плагина через API с наложением файлов нужно также
явно удалить прежние MCP-декларации и совместимые manifest-файлы из
проверенного инвентаря: их отсутствие в ZIP само по себе их не удаляет.
Не меняйте App ID, имя или подключение уже существующего App-backed плагина;
для него используйте предусмотренное обновление навыков.

Этот вариант предназначен для личного/рабочего подключения к существующему
App. Для публичной отправки в каталог используется отдельный маршрут с MCP
endpoint. Поддержку веб-чата проверяйте после установки: сама сборка ZIP
или добавление `.app.json` не доказывает доступность команд.
См. [правила App ID и ограничения импорта](https://learn.chatgpt.com/docs/enterprise/plugin-management#reference-an-existing-app-with-appjson)
и [формат manifest](https://developers.openai.com/plugins/build/plugins#add-an-openai-and-codex-overlay).

## Импорт репозитория

В рабочем пространстве ChatGPT с поддержкой marketplace администратор
открывает **Admin → Plugins → Add → Import marketplace**.

| Поле | Значение |
| --- | --- |
| Source | `https://github.com/Artypoul/gigma-mcp` |
| Path | Оставить пустым |
| Branch / tag / commit | `main` или пусто для ветки по умолчанию |
| Имя marketplace в репозитории | `gigma-mcp` |
| Плагин | `gigma-mcp` / Gigma MCP |

Используйте URL репозитория. Каталоги `.agents/plugins/marketplace.json` и
`.claude-plugin/marketplace.json` уже находятся на своих стандартных местах.
Поле Path задаёт папку marketplace в репозитории; у Gigma это корень, поэтому
туда не нужно вписывать имя JSON-файла или `plugins/gigma-mcp`.

1. Заполните поля и выполните **Import marketplace**. Завершите авторизацию
   GitHub, если её запросит ChatGPT.
2. В **Import results** проверьте результат именно для **Gigma MCP**. Общее
   завершение импорта ещё не означает, что каждый плагин импортирован успешно.
3. Настройте доступность и установку плагина в рабочем пространстве. Политики
   доступа ChatGPT задаются администратором; настройки marketplace в Git не
   выдают пользователям доступ автоматически.
4. Установите или выберите Gigma MCP в поддерживаемом клиенте и выполните
   [проверку инструментов](#проверка-инструментов-и-вход).

Этот путь описан для **администратора рабочего пространства**. Доступность
импорта в личном аккаунте может отличаться. См.
[официальную инструкцию OpenAI по управлению плагинами](https://learn.chatgpt.com/docs/enterprise/plugin-management).

## Обновление существующего marketplace

Откройте **Admin → Plugins → Marketplaces**, выберите ранее импортированный
источник Gigma и нажмите **Sync now**. Для получения новых коммитов источник
должен отслеживать `main` или ветку по умолчанию. Если в поле ref указан SHA
коммита, источник закреплён на этом коммите.

ChatGPT также проверяет обновления источника ежедневно. После синхронизации
просмотрите отчёт по Gigma MCP: ошибочное обновление может оставить предыдущую
рабочую версию. Повторная загрузка ZIP не обновляет GitHub marketplace.
Не удаляйте marketplace для обновления: удаление источника в ChatGPT удаляет
и импортированные из него плагины.

## Доступность MCP в веб-чате и Desktop

В [документации OpenAI](https://learn.chatgpt.com/docs/enterprise/plugin-management)
указано, что импортированный плагин с MCP-декларацией может быть помечен
**Desktop only**, в том числе когда сервер доступен по HTTPS. Наличие навыков
и карточки Gigma не доказывает, что MCP-команды доступны в веб-чате.

Проверьте обозначение доступности в результатах импорта и карточке плагина.
Если указан **Desktop only**, используйте поддерживаемый Desktop-клиент.
Изменение URL сервера, добавление `.app.json` или повторный импорт сами по себе
не отменяют это ограничение хоста. Состояние входа владельца проверяется
отдельно, когда клиент предоставляет инструменты `erp_dialog_*`.

## Конфигурация плагина

| Параметр | Значение |
| --- | --- |
| Каталог плагина в репозитории | `plugins/gigma-mcp` |
| MCP URL | `https://api.auth.gigma.ru/mcp/owner/` |
| Транспорт | Streamable HTTP |
| Авторизация транспорта, если клиент предлагает выбор | None / No authentication |
| Вход владельца | Native callback через `erp_dialog_*` |

Marketplace уже ссылается на пакет с `plugin.json`, `mcp.json` и навыками.
В клиенте, который поддерживает bundled MCP из marketplace, отдельная
регистрация того же сервера не нужна. Для веб-чата используйте маршрут выше.
Сохраните завершающий `/` в MCP URL: адрес без него может
перенаправлять POST.

**None относится к обнаружению инструментов.** Сервер проверяет доступ к
данным проекта по подтверждённой сессии владельца. В пакете нет токенов,
паролей или готовых сессий. Если хост требует OAuth ещё до выдачи
`erp_dialog_*`, зафиксируйте несовпадение транспортного контракта и остановите
эту попытку; не смешивайте OAuth и native callback.

## Проверка инструментов и вход

Выберите Gigma MCP в разговоре и напишите:

> Проверь, какие инструменты Gigma доступны. Пока не начинай вход владельца.

До входа клиент должен предоставить следующие инструменты:

| Инструмент | Назначение |
| --- | --- |
| `erp_dialog_check` | Проверка существующей сессии или подготовка диалога |
| `erp_dialog_start` | Начало выбранного входа или регистрации после согласия |
| `erp_dialog_status` | Состояние текущего подтверждения |
| `erp_dialog_reconcile` | Явно запрошенное восстановление неопределённого результата |
| `erp_dialog_connect` | Завершение подтверждённого входа |
| `erp_dialog_me` | Данные текущего владельца и проекта |
| `erp_dialog_cancel` | Отмена незавершённого диалога |
| `erp_dialog_logout` | Завершение сессии владельца |

Наличие в каталоге защищённых бизнес-инструментов, например
`erp_list_applications`, ещё не предоставляет доступ к данным.

Когда инструменты доступны, напишите:

> Подключи меня к Гигма.

Далее действует [native callback flow](mcp-client-setup.md#native-owner-login).
Агент использует действующую сессию, если она доступна. Для нового входа он
получает номер владельца, предлагает один выбор входа или регистрации и после
подготовки подтверждения показывает номер для звонка. Не передавайте токены,
callback proof или capability в сообщении.

Вход подтверждён, когда `erp_dialog_me` вернул корректный проект и последующее
разрешённое чтение, например списка приложений, успешно.

## Дополнительные форматы установки

### Архив одного плагина

Для отдельного импорта пакета из checkout репозитория выполните:

```text
python build_chatgpt_package.py
```

Получится `dist/gigma-mcp-<version>-chatgpt.zip` с одним каталогом `gigma-mcp`.
Это снимок плагина для клиента с поддержкой ZIP-импорта. Он не содержит
marketplace-каталогов и не создаёт подписку на GitHub-обновления. Ограничения
доступности MCP в клиенте по-прежнему действуют.

### Прямое подключение MCP

Для реальных команд в веб-чате начните с
[подключения MCP-сервера](#команды-в-веб-чате-chatgpt). Оно предоставляет
инструменты; шесть навыков из GitHub автоматически не добавляются.
Для их привязки к существующему подключению используйте описанную выше
сборку с проверенным App ID. Для клиентов с bundled MCP остаётся установка
из marketplace без второго подключения.

## Диагностика

| Наблюдение | Что проверить |
| --- | --- |
| Импорт не находит плагин | Source — URL репозитория, Path пустой, ref существует; проверить Import results |
| После нового коммита остаётся старая версия | Ветка источника и результат Sync now; закреплённый SHA не отслеживает ветку |
| Карточка помечена Desktop only | Использовать поддерживаемый клиент; не считать повторный импорт исправлением веб-доступности |
| Карточка есть, MCP-команд нет | Доступность в клиенте, ошибки импорта, установленная версия и выбранный плагин |
| Сервер проходит read-only проверку, инструментов в чате нет | Подключение и runtime ChatGPT; это не доказательство сбоя Gigma |
| HTTP 401/403 до обнаружения инструментов | Точную ошибку транспорта; не менять способ входа автоматически |
| HTTP redirect | Завершающий `/` в MCP URL |
| Появились карточка выбора и текстовый вопрос | Регистрацию и метаданные; не отвечать дважды |

**Версия 0.3.0:** поле `extensions.com.openai.auth` внутри записи сервера
отклонялось [portable-парсером Codex](https://github.com/openai/codex/blob/b9559ff737000a4fcf7a0e12c3353cca1ea4d008/codex-rs/codex-mcp/src/agent_plugin_config.rs).
В 0.3.1 оно удалено. Обновите старую установку до текущей версии marketplace.
Это исправление парсера сохраняет endpoint и callback-вход; оно не меняет
ограничения доступности импортированных MCP-плагинов в ChatGPT.

Подробнее: [устранение неполадок](mcp-troubleshooting.md) и
[правила доступа](mcp-security-and-approvals.md).

## Проверки для разработчика

В корне checkout репозитория, Python 3.10 или новее и установленный Codex:

```text
python validate_plugin.py
python -m unittest discover -s tests -v
python check_client_registration.py --marketplace-root .
python build_chatgpt_package.py
python check_client_registration.py --archive dist/gigma-mcp-*-chatgpt.zip --regression-check
python check_live_contract.py --timeout 15
```

Проверка с `--marketplace-root .` читает настоящий marketplace-каталог и его
source-путь, сохраняя каталог без изменений во временной копии. Настоящий
загрузчик Codex должен обнаружить один MCP `gigma` и все шесть навыков.
Проверка ZIP выполняется отдельно. Оба режима не устанавливают плагин и не
запускают вход владельца. В CI используется Codex 0.170.0; ошибка запуска
загрузчика завершает проверку с ошибкой.

Отдельное задание CI проверяет установку опубликованного GitHub-коммита через
`codex plugin marketplace add` и `codex plugin add`. Оно сверяет источник,
версию и включённое состояние установленного плагина, затем проверяет сервер
и навыки настоящим клиентом. Скрипт `check_marketplace_install.py` предназначен
только для чистого одноразового GitHub runner и отказывается изменять
существующую пользовательскую конфигурацию.

Live checker выполняет только `initialize`, `notifications/initialized` и
чтение каталогов. Он не вызывает `tools/call`, не отправляет телефон и не
запускает callback. Сохраните версию пакета, Git SHA и результаты проверок;
не сохраняйте идентификаторы сессий, capabilities или персональные данные.
